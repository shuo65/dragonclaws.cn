💓 心跳检查机制说明

💓 OpenClaw 心跳检查机制

配置时间：2026-04-02 | 适用版本：OpenClaw-zh v2026.4.2+

📋 心跳检查是什么？

心跳检查是 OpenClaw 主动执行的例行系统健康检查，每 30 分钟自动运行一次，用于：

  • 📊 监控记忆系统状态（压缩风险检测）
  • 🔄 扫描自改进模块是否有新的学习需要记录
  • 📝 自动更新心跳状态日志

⚙️ 检查流程

当收到心跳轮询消息（Read HEARTBEAT.md if it exists...）时，执行以下检查：

1. Memory Management 检查

  • 计算 ~/.openclaw/workspace/memory 文件夹总大小
  • 预期值：10 KB ~ 200 KB（超过 500 KB 需压缩）
  • 输出当前记忆大小，无异常则继续

2. Self-Improving Check

  • 扫描 ~/self-improving/ 目录
  • 读取 heartbeat-state.md 中的 last_reviewed_change_at
  • 查找自上次检查后是否有新增/修改的文件（排除 heartbeat-state.md）
  • 如有新纠正或反思，追加到对应文件（corrections.md / memory.md / domains/ / projects/）

3. 更新心跳状态

  • 更新 ~/self-improving/heartbeat-state.md 中的 last_heartbeat_started_at
  • 记录 last_heartbeat_result 为 HEARTBEAT_OK
  • 添加本次检查摘要到 Last actions 列表

4. 回复心跳确认

  • 如果一切正常 → 回复 HEARTBEAT_OK
  • 如果有问题 → 回复问题描述（不包含 HEARTBEAT_OK）

📁 关键文件

文件 路径 用途
HEARTBEAT.md C:\Users\用户名\.openclaw\workspace\ 心跳任务定义（PowerShell 脚本、检查清单）
heartbeat-state.md C:\Users\用户名\self-improving\ 心跳执行状态记录（时间戳、动作历史）
memory-manager ~/.openclaw/skills/memory-manager/ 记忆压缩检测和快照脚本

🔧 自定义检查清单

修改 HEARTBEAT.md 可以添加自定义检查任务。示例：

# Email Check (每小时)
# 检查未读邮件
openclaw email unread --limit 10

# Calendar Check (每天 2 次)
# 检查未来 24 小时日程
openclaw calendar events --from now --to "24h"

# Weather Check (需要时)
# 获取所在地天气
weather "河南洛阳"

⏰ 执行时间

  • 默认间隔： 30 分钟
  • 自动调度： OpenClaw 内部定时器触发
  • 执行方式： 每次完整检查后等待 30 分钟，再次执行
  • 日志记录： 每次检查结果追加到 heartbeat-state.md

⚠️ 注意事项

  • 不要频繁修改 HEARTBEAT.md： 此文件由系统自动读取，添加任务时需确保语法正确。
  • 心跳占用资源极少： 主要为磁盘 I/O 和文件统计，CPU 消耗可忽略。
  • 时间可调整： 如需更频繁或更稀疏的检查，可修改 OpenClaw 配置中的心跳间隔。
  • 时区敏感： heartbeat-state.md 中的时间戳使用 UTC+8（Asia/Shanghai）。
  • 手动触发： 可通过发送心跳轮询消息手动触发检查（用于测试）。

📌 最佳实践

  • 每天至少检查一次 heartbeat-state.md，确认心跳正常运行
  • 如果超过 24 小时无心跳记录，需排查 OpenClaw 是否异常退出
  • 记忆大小超过 300 KB 时，手动运行 memory-manager snapshot
  • self-improving/ 目录中的 corrections.md 是宝贵的学习记录，不要删除
