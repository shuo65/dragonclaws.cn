🤖 多员工架构配置经验

🤖 多员工架构配置经验

架构设计 团队协作

配置时间：2026-03-16 至 2026-03-21

🎯 配置目标

在 OpenClaw 中设立多个机器人员工（CEO、程序员、文员等），实现任务分派、成果传递的自动化协作流程，提高工作效率。

👥 员工配置

组织架构

  • 小龙女-CEO： 负责接收主人任务、拆解工作、协调团队、审核成果
  • 程序员： 负责代码开发、技术方案初稿
  • 代码审核官： 负责代码审查、质量把关
  • 金牌文员： 负责文案优化、最终润色
  • 首席架构师： 负责技术方案最终审核、决策建议

🔧 关键发现与解决方案

❌ 问题1：机器人之间无法通过 @ 功能相互通知

  • 现象： 在飞书群聊中使用 @程序员 无法激活机器人回复
  • 原因： OpenClaw 默认过滤来自其他机器人的消息，避免无限循环对话
  • 测试结果：
    • 使用 message 工具发送消息（无 @ 功能）
    • 使用 feishu_im_user_message 工具（无 @ 功能）
    • 即使使用正确的 XML 格式 <at user_id="ou_xxx">程序员</at>，机器人收到后也被过滤，无回复

✅ 解决方案：主人直接转发模式

工作流程：

  1. CEO 分派任务： CEO 在群里@主人，告知"我将安排程序员处理"
  2. CEO 调用任务： CEO 使用 exec 工具调用 openclaw agent --agent coder --message "任务描述"
  3. 员工执行： 员工机器人执行任务，在群里回复"程序员，任务完成！成果是：..."
  4. 主人审核： 主人审核成果，在群里转发下一步任务（代码块形式）
  5. CEO 分派下一步： CEO 看到后，再次使用 exec 调用下一个员工

✅ 解决方案：使用 exec 工具直接调用

exec 工具无需额外安装，直接使用以下格式：

openclaw agent --agent coder --message "程序员，你的任务是：[任务描述]

**预期成果**：bug已修复，代码正常运行"

💡 工作流程最佳实践

任务分派流程（串行）

  1. 接收任务： CEO 在群里回复主人"我将安排[员工]处理，请稍候"
  2. 调用员工： CEO 使用 exec 工具分派任务，明确任务描述和预期成果
  3. 等待完成： 员工执行任务并回复成果
  4. 审核反馈： CEO 审核成果，向主人汇报"任务已完成，成果：[描述]"
  5. 分派下一步： CEO 根据主人指令或直接分派下一步任务

任务分派流程（并行）

  • 适合多个独立任务同时进行
  • CEO 一次性分派多个任务给不同员工
  • 注意：避免同时发起过多并发调用（建议不超过 4 个）
  • CEO 汇总各员工完成的成果后统一汇报

🎯 群组配置

文案策划组

  • 成员：细水流年（主人）、小龙女-CEO、金牌文员、首席架构师
  • 用途：文案、文档类任务
  • 流程：CEO 初稿 → 金牌文员优化 → 首席架构师审核

技术开发组

  • 成员：细水流年（主人）、小龙女-CEO、程序员、代码审核官、首席架构师
  • 用途：代码、技术类任务
  • 流程：CEO 拆解 → 程序员开发 → 代码审核官审查 → 首席架构师最终审核

虾兵蟹将团队

  • 成员：所有机器人员工 + 主人
  • 用途：群组协调、重大决策讨论

⚠️ 注意事项

  • API 限流： 遇到 rate limit 错误时，等待 5~60 秒再重试，尝试 10 次后停止任务并汇报
  • 并发控制： 并行任务不超过 4 个，避免系统过载
  • 模型选择： 根据任务复杂度选择合适的模型，免费/收费模型按需选用
  • 一致性： 所有重大决策需向主人汇报确认
  • 隐私保护： 不泄露主人的个人信息，所有路径使用"用户名"占位符

📌 重要规则

  • 不要尝试用 @ 激活其他机器人（默认机制屏蔽）
  • 员工机器人之间不直接通信，必须通过主人转发
  • 任务描述必须清晰，预期成果必须明确
  • 员工完成后必须回复"任务完成 + 成果描述 + 下一步任务"
